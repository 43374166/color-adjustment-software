# 局部高光 / 阴影（v3 影调原型）

本轮把 **高光 / 阴影** 从“显示域全局 1D LUT”改成“渲染后的 guided 局部曝光”，
保留 Lightroom 风格六滑块 UI；曝光、对比度、白色、黑色仍走原有语义。

## 行为

- 曝光：场景线性纯增益 `×2^EV`（不变）。
- 对比度：显示域端点固定 S 曲线（不变）。
- 白色 / 黑色：显示域端点 LUT（不变）。
- 高光 / 阴影：在最终画面（几何 / 蒙版之后）上构建低分辨率 guided 亮度基底，
  按基底 EV 做局部曝光：
  - 高光只作用于基底 EV > 1.2 的区域，−100 最大 −1.2 EV；
  - 阴影只作用于基底 EV < −1.5 的区域，+100 最大 +1.2 EV；
  - 中灰附近权重为 0，纯黑乘增益仍为 0。

实现位置：`crates/core/src/tone.rs` 的 `LocalToneBase` / `apply_local_tone`。

## 为什么放在渲染后

当前预览 / 导出仍是 RGBA8。若在场景线性阶段做局部曝光，需要把整条管线改成
浮点或 16bit，并把基底一起传进分块导出；这一版先在最终 RGBA8 上做，保证：

- 预览、区域帧、分块导出完全同一套代码；
- 分块导出在拼完整帧后只跑一次局部影调，不会出现条带接缝；
- 后续升级浮点管线时，只需把 `LocalToneBase::build` 移到 tone 之前。

## GPU

`PreviewSession` 在 `highlights != 0 || shadows != 0` 时返回
“高光 / 阴影局部影调使用 CPU 预览”，iOS 侧同时直接跳过 GPU 会话。
GPU 直接使用 `ColorPipeline` 的路径（Windows UI）尚未接入局部影调；
它的高光 / 阴影仍走旧 LUT，属于后续工作。

## 测试

- `tone.rs`：局部高光只压亮区、局部阴影只提暗区、中灰 / 纯黑不动、
  guided 基底能区分亮暗区、线性通道比例保持。
- `preview.rs`：分块渲染与整帧渲染的局部影调最大差 ≤ 2/255。
- 实拍 A/B：`render-cpu` 已改为走完整 `render_memory_rgba`，可直接对比。

## 调参

`LOCAL_HIGHLIGHT_MAX_EV` / `LOCAL_SHADOW_MAX_EV` 控制 ±100 的最大曝光量；
`local_gain_ev` 里的 `smoothstep` 边界控制作用亮度范围。当前 1.2 EV /
1.2–3.2 与 −4.5–−1.5 是首版经验值，后续用真实样片继续收敛。
