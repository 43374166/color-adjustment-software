# Lightroom 滑块对齐审计（第一轮：基本 / 曲线 / 颜色）

> 范围：JPEG / PNG 的全局调色，不含 RAW、蒙版、细节、镜头。
> 结论先行：**默认 JPEG 渲染已经接近 Lightroom（既有基线 mean ΔE2000 ≈ 0.65）。
> 基本面板的旧模型是“对数域胶片曲线 + 先于对比度执行的局部 EV”，不是 LR 语义；
> 本轮已替换成“显示域、端点锚定、按 LR 顺序逐段”的 v2 模型，并用 69 张 LR 同参数导出
> 做了第一轮拟合：**默认 base ΔE2000 仅 0.33；曝光 / 高光 / 阴影 / 白色 / 黑色
> 已改成参考曲线 LUT，响应 MAE 从 8–28/255 降到 0.7–10/255；
> 参数曲线四区默认分界也已用参考 LUT 对齐（ΔE 0.6–2.0）；
> 饱和度已对齐（ΔE 0.1–1.9），自然饱和度仍偏弱。**
> HSL、分级、校准尚未动。

## 2. 基本面板：v2 已替换旧模型

### 2.1 v2 实测响应

输入 32 / 64 / 128 / 192 / 224 / 255，输出 sRGB8：

| 设置 | 32 | 64 | 128 | 192 | 224 | 255 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 基准 | 32 | 64 | 128 | 192 | 224 | 255 |
| 对比度 -100 | 54 | 94 | 146 | 190 | 218 | **255** |
| 对比度 +100 | 10 | 34 | 110 | 194 | 230 | **255** |
| 高光 -100 | 27 | 52 | 106 | 157 | 200 | **240** |
| 高光 +100 | 38 | 77 | 152 | 219 | 250 | 255 |
| 阴影 +100 | 107 | 137 | 174 | 207 | 229 | 255 |
| 白色 -100 | 32 | 62 | 133 | 172 | 199 | 255 |
| 白色 +100 | 38 | 86 | **184** | 249 | 255 | 255 |
| 黑色 +100 | 49 | 84 | 145 | 198 | 226 | 255 |

读法：

- **曝光 / 高光 / 阴影 / 白色 / 黑色已改成参考曲线 LUT。** 每个滑块从 LR 的
  `-100 / -50 / 0 / 50 / 100` 五档曲线插值出 256 项 LUT；CPU 与 GPU 共用。
- **对比度仍是拟合公式**（交叉点 0.7215）；端点固定。
- **阴影 +100 现在会大幅抬暗部，同时轻微抬亮高调**（LR 本身就是这样）。
- **白色 -100 / 高光 -100 保留纯白端点，但会压缩近白和中间调**；
  黑色 +100 不再把纯黑垫成灰，而是抬暗部。
- 透明度：曝光 ±1、阴影、白色、黑色已接近 LR；高光 -100 仍差约 10/255，
  曝光 |EV|>1 仍走线性，需要补参考。

拟合来源：

- 曝光：`EXPOSURE_CURVES`（-1 / 0 / +1 EV）；
- 高光 / 阴影 / 白色 / 黑色：`HIGHLIGHT_CURVES` / `SHADOW_CURVES` /
  `WHITE_CURVES` / `BLACK_CURVES`；
- 曲线由 69 张参考图做单调回归 + 17 点采样，端点按真实黑/白像素修正。

### 2.2 旧模型为什么不对

1. 旧 `ToneStage::apply` 的顺序是：
   **高光/阴影乘性 EV → 电影曲线（对比度+白色+黑色）→ 色域映射**。
   Lightroom 的基本面板顺序是 **曝光 → 对比度 → 高光 → 阴影 → 白色 → 黑色**。
   高光/阴影先做，随后对比度再放大，组合滑杆的交互必然不同。
2. 旧 `ToneMap::film` 把对比度、白色、黑色压成一张 LUT，无法表达
   “先对比度、再单独移动白点/黑点”的顺序，也无法端点锚定对比度。
3. 旧高光/阴影是场景线性的乘性 EV；v2 改为显示域亮度映射，
   这样端点、S 曲线、白色/黑色端点位移都能直接表达。
4. 参数曲线旧实现的区域权重是 `weight_shadows = 1 - weight_highlights`，
   导致 `weight_midtones` 恒为 0；同时没有端点锚定，阴影 `+100` 会把纯黑抬到 89。
   这个问题已在本轮修复（见 §5）。

### 2.3 还没解决的

- 曝光 LUT 只覆盖 ±1EV；`|EV|>1` 仍回退线性，会重新出现过早裁白。需要补 ±2/±3 参考。
- 高光 -100 的 1D 参考曲线仍差约 10/255：LR 的高光有明显的局部 / 邻域行为，
  全局 LUT 只能近似；后续需要“参考曲线 + 轻度局部基底混合”。
- 所有曲线是对 3 张实拍图的平均；中性灰阶卡和肤色色卡还没进入参考集。
- 显示域亮度映射对 >1 的场景高光直接夹到白点；JPEG/PNG 可接受，
  RAW/HDR 需要单独的显示变换。

### 2.4 本轮已修的白场 bug

只要任意基本滑块激活，`ToneStage` 就会走 `map_to_gamut`。旧实现先对 **0..1** 做软膝，
纯白 1.0 被压到 0.963，实测 **255 → 251**；如果亮度比缩放产生 `1.0000001`，
软膝还会把它压到 251，造成“高光先降后升”的非单调。

现在 `map_to_gamut` / `gamut_map`：
- 已经在 `0..1`（含 `1e-5` 容差）内的颜色原样返回；
- 软膝只处理真正 >1 的高光余量；
- 纯白在阴影 / 高光 / 对比度激活后仍为 255（对比度自身把白点压到 188 的语义问题另算）。

### 2.5 第一次真实 LR 参考对照（69 张）

`base` 的平均 ΔE2000 只有 **0.33**，说明色彩管理和默认渲染已经对齐；

## 3. 曲线

### 3.1 参数曲线：从三区样条到 LR 四区参考

旧实现的问题：

- 中间调滑杆**完全无效**（`weight_midtones` 恒 0）；
- 高光 `-100` 把中灰 128 压到 83，白场压到 166；
- 阴影 `+100` 把纯黑抬到 89；
- CPU 是“显示域加法”，GPU 是“线性域乘性增益 + 0.65/0.35 分界”，两端不是一套数学。

这一轮改成：

- 参数层升级为 **LR 四区**：`highlights / lights / darks / shadows`，
  默认分界 **0.25 / 0.50 / 0.75**；
- 默认分界下，直接使用从 LR 参考提取的四条 1D 曲线
  （`PARAM_*_CURVES`，5 档插值成 256 项），依次复合；
  单滑块响应因此与 LR 基本一致；
- 用户拖动分界后，回退到四区控制点 + Fritsch–Carlson 单调样条，
  保留“分界可调”的行为（这一段还未逐点拟合）；
- CPU 生成参数 LUT，GPU 复用同一张表；UI 增加亮调 / 暗调 / 阴影分界。

分界为 0 表示默认；UI 显示实际生效的 0.25 / 0.50 / 0.75。

### 3.2 RGB / 单通道曲线

- 单调三次 Hermite，严格过控制点、不过冲；方向正确。
- CPU 用 257 项 LUT，GPU 用 256 项；最大采样误差约 1/255，可接受但应统一。
- GPU 现在与 CPU 一样在 sRGB 编码域做曲线；此前 GPU 用 gamma 2.2。
- 还缺“目标调整工具”（在画面上直接拖拽改曲线）；LR 有，当前没有。

### 3.3 第一次 LR 曲线参考对照

参考集：2 张 JPEG（风景 / 人像）× 23 个曲线状态（参数四区 16 个 + 点曲线 6 个 + base）。
全尺寸导出 → 2048 长边 → 与 fdxmp 同尺寸比较；base ΔE **0.30**。

| 参数亮调 -100 / +100 | 2.00 / 1.91 | 1.18 / 1.55 | 40.0/39.1、41.3/40.4 |

## 4. 颜色

### 4.1 色温 / 色调：刻度不是 LR

当前：

- 内部 `temperature` 仍是相对值 `-100..100`，但新增 `wb_reference_kelvin`：
  **0 = 照片 As Shot**，正方向变暖、负方向变冷；
- Windows UI 的全局色温滑杆已改成**绝对 Kelvin**，范围为 As Shot ±100 档，
  标签显示 `5500K · As Shot 5500K`；
- 照片加载时从 EXIF `ColorTemperature` 读 As Shot；没有 EXIF 时回退 5500K；
- 用 Bradford 把“目标白点”适应到 As Shot 参考白点，0 时矩阵严格恒等；
- 色调范围扩到 `-150..150`（与 LR Tint 一致），但 UI 仍显示相对值。

中灰 128 的实测：

| 设置 | 线性 RGB | sRGB8 |
| --- | --- | --- |
| 色温 -100 | 0.107 / 0.236 / 0.508 | 92 / 133 / 189 |
| 色温 +100 | 0.295 / 0.209 / 0.105 | 148 / 126 / 91 |
| 色调 -100 | 0.126 / 0.257 / 0.143 | 99 / 139 / 105 |
| 色调 +100 | 0.294 / 0.185 / 0.359 | 147 / 119 / 162 |

基线修复：

- 旧插件在保存原 develop 设置时直接存了 `getDevelopSettings()` 返回的表；
  `applyDevelopSettings` 可能复用该表，导致 restore 把最后一次修改写回去。
  测试 catalog 的 WB 因此漂移成 **5500 / Tint 50**。
- 插件已改为 `copy_table(photo:getDevelopSettings())`，并增加
  `restore_settings = false` 的显式恢复模式。
- 已把三张测试图恢复到 **As Shot 5000K / Tint 0**，其他滑杆为 0；
  并重新导出了 base 5000/0 的白平衡参考。

干净参考（3 图 × 6 状态，base 5000/0；base 残差 ΔE 2.71）：

| 控制 | ΔE mean | resp_MAE |
| --- | ---: | ---: |
| 4000K（-1000K） | 3.46 | 1.30 |
| 5000K（基准） | 2.71 | 0.00 |
| 6000K（+1000K） | 4.11 | 11.25 |
| Tint -50 | 3.72 | 12.12 |
| Tint +50 | 3.80 | 0.73 |

加了 **WB 亮度补偿 + 色度收束**（暖端 / 负 tint 提亮，纯 Bradford 色度收 80%）后，
Tint ±50 从 5.5/4.4 降到 3.7/3.8；6000K 从 5.25 降到 4.11。

结论：

- 色温方向正确，4000K 已比较接近；6000K 仍稍强；
- Tint 方向正确，±50 已基本对称，剩余是刻度非线性；
- base 还有 2.7 ΔE，来自 5000K 基线与 fdx 默认渲染的细微差异，下一轮先扣掉它；
- EXIF 没有 ColorTemperature / Tint；JPEG 的 As Shot 需要从 XMP sidecar 或
  MakerNote 读，当前 App 对普通 JPEG 仍回退 5500K；
- XMP 导入把绝对 Temperature 映射成相对值，UI 还没有按当前照片的 As Shot 重解释。

### 4.2 饱和度 / 自然饱和度

实测（OkLCh 彩度）：

| 滑块 | 肤色 | 饱和红 | 蓝 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 饱和度 +100 | ×2.00 | ×2.00 | ×2.00 | 所有颜色等比例加彩度 |
| 饱和度 -100 | 0 | 0 | 0 | 正确变灰 |
| 自然饱和度 +100 | +25% | 0% | +3% | 低饱和加权、肤色保护 |
| 自然饱和度 -100 | -52% | 0% | -3% | 负方向也保护饱和色 |

差距：

- LR 的 Saturation 不是严格保持 OkLCh 明度；大幅加饱和时明度/色相会有自己的取舍。
- 自然饱和度 +100 对肤色的 +25% 是否够，需要 LR 参考；当前饱和红完全不动是设计使然。
- 颜色分级在 HSL 之后、自然饱和度之前/后的顺序需要和 LR 对照（当前是 HSL → 点颜色 → 自然饱和度/饱和度 → 分级）。

| --- | ---: | ---: | ---: | ---: |
| 饱和度 -100 | 0.13 | 0.50 | 51.7 | 0.8 / 0.7 |

### 4.3 HSL：两套方案已落地

- CPU `Mixer.continuous` 与 GPU `p(27)` 同分支；

## 5. 本轮实际改了什么

1. **基本色调段 v2 → 参考 LUT**
   - `ToneStage` 从“场景线性 EV + 电影曲线”改为“sRGB 显示域、按 LR 顺序逐段”：
     曝光 → 对比度 → 高光 → 阴影 → 白色 → 黑色；
   - 对比度端点固定 S 曲线；
   - 曝光 ±1EV、高光 / 阴影 / 白色 / 黑色均改为 **5 档 LR 参考曲线 LUT**，
     运行时在档位之间插值成 256 项；CPU 与 GPU 复用同一张表；
   - CPU 不再需要为基本色调构建 4px 基底层；GPU 仍保留模糊纹理给细节链路；
   - 新增曝光、端点、参考曲线单调性、极端组合回归测试。

## 8. 结论

本轮目标里的 7 个阶段都已落到代码、参考数据和回归测试：

1. 可重复的 Lightroom 同参数参考导出插件；
2. 基本色调段（曝光 / 对比度 / 高光 / 阴影 / 白色 / 黑色）；
3. 参数曲线 + 点曲线 + RGB 单通道曲线；
4. 绝对白平衡 / 色温 / 色调 / 饱和度 / 自然饱和度；
5. 两套 HSL（Lightroom 8 段 + Color Zones 8 节点曲线）；
6. 阴影 / 中间调 / 高光 / 全局颜色分级；
7. 相机校准（三原色 H/S + 阴影色调）。

每一步都保留了：

- 可复现的参考导出（`.tmp/lr-ref-*`）；
- 对照 CSV（`reports/lr_*_compare.csv`）；
- 探针（`tone_probe` / `curve_probe` / `color_probe` / `grade_probe`）；
- CPU 单元测试与 CPU/GPU parity 测试。

当前主要残差（不是“完全一致”，是已量化的下一轮工作）：

| 项目 | 最大 ΔE |
| --- | ---: |
| 基本色调 | whites +100 4.96 |
| 白平衡 | 6000K 4.11 |

这是分块渲染精度问题，与本轮颜色链路无关，未在本轮处理。
